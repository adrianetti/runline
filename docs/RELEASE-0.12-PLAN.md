# Runline 0.12 — coach insight

Scope agreed from the 4 November 2026 field feedback. The repository stays private while an open-source/Play Store release is prepared. Private GPX files, API credentials and diagnostic exports never enter Git or marketing assets.

1. **Explain coaching.** Save local, bounded diagnostic events for actual TTS starts, with phrase, source, wall-clock time, active time, latest GPS fix/time/accuracy, pace and estimated terrain. Distinguish generated/queued/dropped speech from speech that started. Provide an activity timeline and a diagnostics screen; sharing is explicit, with coordinates excluded by default.
2. **Improve contextual encouragement.** Avoid delayed direction claims, recheck terrain before speech, and add encouragement for sustained progress, goal progress, consistent running and returning to target. Keep the shared quiet intervals and milestone priorities; no extra music interruptions simply to fill silence.
3. **Show AI usage.** Track this installation's API requests, model, operation, latency, response code, reported input/output/cache tokens and estimated supported-model cost. Exclude keys, request bodies and health notes. Unknown usage/cost stays unknown; opening this screen makes no API call.
4. **Show a moving slope profile.** Replace the straight slope instrument with a small causal elevation profile at the same size, preserving pace-first hierarchy and the larger backdrop. Keep observed history when a numerical grade is uncertain; never invent flat ground or connect missing GPS heights. Seeking, pause, gaps and reduced motion must be deterministic.
5. **Finish with a useful review.** Persist an optional background review request after recording is safely saved, allow time for journal/effort entry, use current goal, this session, comparable history and weekly volume, and show a short structured review: win, focus, next session. Notify when ready and deep-link to the saved result. Network/credential failures must be visible, with bounded attempts and no duplicate paid generations on reopening/recreation.
6. **Swipe between the two tabs.** Enable intentional horizontal swipes on idle Record/Activities; preserve vertical scrolling, controls, system edge-back and map/replay gestures.
7. **Prepare public distribution.** Add real app screenshots using synthetic data and concise README presentation. Document licensing, secret/history review, imagery terms, privacy/data safety, signing, target-SDK/native-library compatibility, Play account/testing requirements and store assets. Publication and license choice remain separate decisions.

Validation: meaningful unit regressions for diagnostics/privacy, usage, terrain reversals, encouragement, causal profile and review state/format; existing recorder/recovery tests; build/lint/security/resource checks; two bounded native visual passes covering English/Spanish, dark mode, large text and landscape; signed-update retention and background/notification checks. Merge only after every applicable GitHub check passes on the final head.
