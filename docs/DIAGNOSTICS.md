# Local coaching diagnostics

Version 0.12 adds **Settings → Diagnostics** and an activity's **… → Coach log**. **AI → AI usage** opens request accounting directly. These tools make no API call when opened.

Coach recording is on by default for this version and can be disabled independently. Events include queued/rejected prompts, expired/replaced/context-invalidated prompts, actual TTS starts, completion and interruptions. A queued prompt is not evidence that the runner heard it. A TTS start indicates that Android started the utterance; it does not prove headphone audibility.

A speech event stores wall-clock milliseconds, active recording time, the most recent GPS fix with its separate timestamp and horizontal accuracy, estimated pace/grade and cue/source. The fix is an observation, not an exact surveyed position at speech time. From 0.14, terrain comes from independent mapped heights and events include `terrain_source`; unknown coverage produces no hill-specific cue. Older events retain their original GPS-based meaning. No retrospective speech log can be reconstructed from an older GPX.

Logs stay in private app storage, outside automatic backups. Each log is bounded near 512 KB and older events are trimmed; up to 100 session logs are retained. A torn final write does not discard preceding complete events. Optional diagnostic failures never enter recording persistence. Deleting an activity removes its coach log. Clear diagnostics preserves activities and reviews. Newly recorded events may appear after a clear while coaching continues.

The timeline defaults to TTS starts. Expand a message for GPS details, or choose **Replay here** to jump to its saved fix. **Show queued and skipped prompts** exposes scheduling decisions. Sharing uses Android's chooser. Coordinates are excluded by default; a separate explicit option includes them. Spoken text and timestamps remain in both exports and should be reviewed before sharing publicly. There is no automatic upload to developers.

AI request accounting records operation, model, time, latency, HTTP response code, reported input/output/cache tokens and estimated supported-model USD cost. It excludes credentials, request/response bodies, coordinates and profile fields. Requests without reported usage retain unknown token counts; unsupported custom models retain unknown costs. Summary totals cover retained records on this installation, not an Anthropic account or previous app versions. Local retention/deletion means this is not a billing ledger.

Price estimates use standard global list rates checked on 4 November 2026 for Haiku 5.5, Sonnet 5.5 and Opus 5.5, with Haiku's input tier and reported cache TTLs handled separately. Missing cache-write TTL details make the cost unknown. Taxes, discounts, other clients and future price changes are outside this estimate. See [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing).

Automatic post-run review queues are persisted separately. With AI and automatic reviews enabled, a completed recording queues one job after a 90-second journal-entry window and waits for internet/Android scheduling. Actual execution can be later. The worker rechecks consent/key/settings, loads saved details, and produces a compact structured review. Completed results survive the screen and produce an optional Android notification that opens the saved review. Notification permission/channel settings still apply. An interrupted or failed HTTP attempt is not silently repeated; the review screen offers an explicit retry. Reopening or rotating never creates a second paid generation. Force-stop suspends Android background work until the app is opened again.

New recordings also include reported `vertical_accuracy_m` in coach events. Missing legacy accuracy stays null. This field is separate from horizontal `accuracy_m` and helps explain rejected terrain estimates.
