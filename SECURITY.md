# Security

Do not post credentials, personal routes or an exploitable vulnerability in a public issue.

Use GitHub's **Security → Report a vulnerability** for a private report. Describe the affected version, impact, and a minimal synthetic reproduction. No real activity file or API key is needed. Reports are handled by volunteers; no response-time guarantee is offered.

For ordinary bugs, use the issue template. Update to the latest signed release when available. Keep the same installation to retain locally stored recordings, and export important activities before uninstalling or clearing app data.

Runline's optional AI connection uses your own provider key. Never include that key in logs or screenshots. Signing keys and development credentials are kept outside source control and are not supplied to pull-request builds.
